### Licensing constraints that change the recommendation

The [rembg README](https://github.com/danielgatis/rembg#models) currently names `bria-rmbg` as default and explicitly distinguishes code from model licenses. [BRIA's official model card](https://huggingface.co/briaai/RMBG-2.0) limits free weights to noncommercial use and requires a commercial agreement. Do not use an implicit default for DVNI. [U-2-Net](https://github.com/xuebinqin/U-2-Net/blob/master/LICENSE) provides an Apache-2.0 upstream candidate, but a future test must still record the exact converted checkpoint origin, checksum and applicable weight terms; this iteration has not cleared/downloaded any weights. Source-photo rights remain independent of all model licenses.

[Remotion's current license](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md) is a custom free/company license, **not MIT**. It allows specified individuals/small entities and evaluation, requires a company license outside eligibility, restricts reselling derivatives, and notes upcoming 5.0 changes. It is **HOLD**, not installed; any future adoption must review the pinned version and actual entity/use-case eligibility rather than assuming that open source means unrestricted commercial use.

## Canva: four distinct boundaries

Official documentation now says Apps SDK, Connect APIs and MCP are unified under the **Canva Developers SDK**. The runtime/auth surfaces remain distinct for BrainOS architecture.

### A. Connect / REST (a future BrainOS integration)

[Current REST reference](https://www.canva.dev/docs/apps/rest-apis/reference/designs/) covers design metadata/pages/datasets, assets, imports/exports, folders, autofill, analytics, merges/resizes and newer generation/transformation endpoints. These need an independently authorized app, correct OAuth scopes, API readiness and actual user capabilities. BrainOS currently has **no Canva OAuth/API adapter**; a connected ChatGPT session does not give the server reusable credentials.

[Autofill](https://www.canva.dev/docs/apps/rest-apis/autofill-guide/) populates explicit template/design datasets; it does not determine the best composition. Current docs include Pro/Teams/Enterprise eligibility, so do not repeat the outdated Enterprise-only assumption. Query [user capabilities](https://www.canva.dev/docs/apps/rest-apis/capabilities/) instead of guessing a plan. Design metadata routes are not general arbitrary element-layer editing endpoints.

[Design generation](https://www.canva.dev/docs/apps/rest-apis/reference/generations/create-design-generation-job/) is currently preview, consumes AI allowance and has limited supported design types. [Image transformation](https://www.canva.dev/docs/apps/rest-apis/reference/image-transformations/create-image-transformation-job/) is preview, currently background removal, requires capability and returns a new asset without intermediate stages. Neither is used here; do not assume free credits or stable/public-app availability.

### B. Editor / Apps SDK

The current [Design Editing API](https://www.canva.dev/docs/apps/design-editing/) supports editable elements, geometry, text formatting, grouping and element ordering inside an authorized Canva editor session. It exposes relative insertion/movement for layering and must respect locked/unsupported elements. This can implement more spatial operations than the REST metadata surface. It needs an app/editor integration and user interaction/permissions; it is not a headless BrainOS design engine. Composition quality, optical type balance, crop relevance, mask edge judgment and storytelling still require Daniel/C#2 review. No app is built.

### C. ChatGPT's connected Canva tools (inspected definitions, not executed)

This session exposes search/metadata/page thumbnails/rich text reads; brief-based design creation; image generation; uploads/imports; image-to-design conversion; background removal; resizing; page merges; brand-template/autofill; and **editing transactions**. `start_editing_transaction` exposes editable elements; `perform_editing_operations` explicitly supports replace/find text, insert/replace media, position, resize, delete elements, format text, title and autofill labels. Temporary edits require preview and explicit approval before commit. Page ordering/merges are separate and require exact-operation approval.

The exposed editing operation union does **not** contain arbitrary mask-path creation, layer reordering, font-family selection, custom glyph geometry or a general canvas drawing command. Do not infer these from the more extensive Apps SDK. Image-to-design creates an independent design and may reconstruct photos poorly. Rich-text reads are not full spatial inspection. Tool exposure also does not prove this account's plan can execute every operation. No Canva designs, assets, transactions or generations were created during this audit; no allowance was consumed.

### D. Local preprocessing before Canva

Future local operations can produce transparent cutouts/masks, reviewed crops, licensed glyph paths, evidence-accurate SVG charts, and self-contained PNG/SVG layers with checksums. Import those as source material with exact copy, intended stacking, dimensions, provenance and rights. A flattened PNG cannot guarantee editable typography; reconstruction is an optional lossy step, not equivalent to preserving layers. Keep source/intermediate files and scene associations even when Canva returns only a final export. The present private handoff/export/import boundary already supports this manual exchange and retains human review.

**BrainOS can prepare deterministic materials and capture evidence. C#2/Daniel must validate the visual grammar.** No template, tool output or reported lab approval bypasses authoritative asset rights, exact revision or final publication approval.
